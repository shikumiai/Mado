# Mado 初期運用

商品写真と事実 → 3つの制作方法で画像・見出しを制作 → 人の理由付き比較 → 1案選択 → 1回修正して納品。
最初は運営が制作・回答者募集・入金確認・報酬支払を取りまとめる。AI診断を人間の感想として表示しない。

## 画面
トップ /pilot（依頼一覧・受付） /pilot/[id]（見積・素材・比較・納品） /pilot/manage（運営） /pilot/join（制作方法提供者の応募）
料金は都度見積、見積への同意は入金ではない。運営が入金を別途確認し制作へ進める。
受注5件は運営が受注可否を決める目安。申し込みだけで納期や回答者人数を保証しない。

## 表現
Noto Sans JP、青灰 #172b3a、明るい青 #8cbeee、淡青 #eaf2f9、白 #fff、赤茶 #b04436。
主役は3案を横並びに比べる机。派手な発光や装飾的な統計は使わない。
暗色・明色はOS設定へ追従。スマホは1列、キーボードフォーカスを表示。デモと実績を明確に区別。

## 比較
|構成|今回の判断|理由|
|旧Mado: ホームページ作成・編集|比較対象として保持|新サービスは制作物の比較・選択が中心。旧申込・課金への新規導線を止める。既存の顧客サイトとデータは維持。|
|既存GitHub + Vercel + Supabase|採用|認証・DB・画像保存・公開先がある。既存の1アプリ内で追加できる。|
|Google Cloudへ移設|今回は採用しない|初期の手動制作では別の実行基盤は不要。自動画像処理が増えた時点でジョブ実行だけ比較する。追加プロジェクトや有料契約を作らない。|

## 権限
利用者は自分の依頼だけを読める。依頼時に未使用UUIDと所有者を固定。
見積・進捗・結果はplatform_adminsだけが更新。利用者は提示された見積への同意と3案の選択だけを更新。
画像は非公開バケット、所有者または運営のみ。URLは短時間の署名付き。
制作方法の応募内容・プロンプトは応募者と運営だけが閲覧。他の顧客へ公開しない。
画像のAI処理と比較協力者への限定共有は依頼時に明示して同意を得る。

## 将来
注文が繰り返され、品質と手動対応時間が見えた後にAI実行・決済・報酬台帳を自動化する。
運営が受け取る代金と参加者報酬は別物。報酬額・利用範囲は参加前に個別合意する。
