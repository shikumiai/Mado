# Mado テンプレシステム v3（設計の正）

> 2026-09-06 / 設計: Fable 5.1。Lyo 指示「10業種に必要な機能を持たせ、機能ごとに UI/UX を5種類、
> 色は先に決めて選ぶ前から塗り替わり、統一が目で分かる」を形にする北極星。
> 見た目の作法は `docs/ART_DIRECTION_V2.md`、品質は web-design スキル（80点未満は不合格）に従う。

## 0. 一行で
**サイトは「機能（セクション）」の組み合わせ。機能ごとに5つの見せ方、色はお客のもの、業種ごとに必須機能を揃える。**

## 1. 3つの柱
1. **色エンジン**（第1段で実装）: 代表カラー＋サブ最大2 → `--tpl-*` 変数一式（派生の淡/濃・コントラスト安全な文字色）。
   全セクション・全SVGが変数で塗られるので、色を変えると**全体が同時に**変わる＝統一が目で分かる。
   テンプレは初期プリセットを持ち、お客が選べば全面上書き。
2. **機能カタログ × 5変種**: 下の14機能それぞれに、意図の違う5つのレイアウト。`sections[].variant` で選ぶ。
3. **10業種テンプレ**: 機能の並び＋各機能の既定変種＋初期パレット。業種の**必須機能**を欠かさない。

## 2. 機能カタログ（14）と5変種の意図
変種は「色違い」でなく**レイアウトの型の違い**。5つは原則この5系で作り、機能に合わせて名前と中身を最適化する。
- **A 整列**（grid・カード）/ **B 誌面**（大小・非対称・雑誌）/ **C 一覧**（行・帯・密度）/ **D 主役**（1点を大きく・横送り）/ **E 静寂**（余白・線・最小）

| # | 機能 `type` | 役割 | 5変種（名前＝意図） |
|---|---|---|---|
| 1 | `hero` | 主張＋CTA＋絵 | 主張1枚（大見出し＋1絵）/ 分割（文と絵を左右）/ 全面（写真全面＋文）/ 窓（枠の中に実物/写真）/ 静寂（文字だけ・余白） |

## 4. アーキテクチャ
- `config.sections[] = { type, variant, visible, label, ...data }`。**Renderer は1本のディスパッチャ**: `type` と `variant` で部品を選び、`--tpl-*` を注入して描く。3つの巨大 Renderer は、この部品群へ分解・移行する。
- 部品の置き場: `src/components/sections/<type>/<variant>.tsx`（例 `works/editorial.tsx`）。共通の型 `SectionProps { config, data, palette, editMode... }`。
- 色: 第1段の `src/lib/palette.ts`。部品内の色は**必ず**変数（`var(--tpl-primary)` 等）。生 hex を書かない（テンプレ固有色は初期プリセットにのみ）。
- 詳細ページ: `src/app/[siteSlug]/[section]/[id]/page.tsx` の汎用詳細（works/staff/menu/news）。
- 編集: エディタは `variant` の切替と色の変更を提供（第4段）。保存は既存 `saveSiteConfig`。

## 5. 申込の流れ（v3）
1. **色を決める**（代表＋サブ最大2・プリセットあり・パレット帯で統一を可視化）
2. **業種を選ぶ**（10）→ 3. **テンプレ/見せ方を選ぶ**（その業種の構成が、**選んだ色で塗り替わった実物**として並ぶ。各機能の変種はここで既定を提示し、切替は編集画面でも可）
4. 会社情報 → 5. URL → 6. 公開（既存の signup 経路）。

## 6. 実装順
- **第1段** 色エンジン＋色先行の申込＋塗り替わるプレビュー（進行中）
- **第2段a** 機能カタログの前半7（hero/strengths/services/works/menu/staff/voices）×5変種
- **第2段b** 後半7（flow/faq/news/access/booking/contact/company）×5変種 ＋ 一覧→詳細
- **第3段** 10業種テンプレの構成・初期変種・プリセット・デモ config（実コンテンツ、Lorem 禁止）＋ industry-registry 再編
- **第4段** 見せ方（variant）と色の切替UX（申込と編集画面）
- 各段で build/tsc 緑＋**プレビューの目視**。scoring 60%「スクショが営業資料に使えるか」を各業種で通す。

## 7. 合格条件
1. 色を変えると、全セクション・SVGが同時に統一して変わる（統一が目で分かる）。
2. 10業種すべてに必須★機能がある。詳細ページはデータ1件追加で増える。
3. 各機能の5変種が**レイアウトとして別物**で、どれも ART_DIRECTION_V2 の除外リストに触れない。
4. 各業種のデモが「完成した会社のサイト」に見える（グレー箱・Lorem・空白なし）。

## 8. 本番水準の中身（2026-09-09 Lyo 指摘「テンプレの中身そのものを本番で最初から使える水準に」）
**目的**: テンプレを選んだ時点で「そのまま公開できる会社サイト」に見えること。写真を送れば差し替わるが、送る前でも恥ずかしくない。
**現状**: 文章は実内容だが、写真が無く SVG の平面イラスト（art.tsx）で埋まっている。旧写真（`public/images/templates/*`）は 800px の欧米 stock で、3系統には無く、0KB の壊れファイルもある。
**条件**: 写真は日本の中小企業の実景に見えること／お客の写真に差し替えても枠が動かないこと／色エンジンと喧嘩しないこと。

### 8.1 写真セット（テンプレごと・ファイル名固定）
置き場 `public/images/templates/<templateId>/`。生成は写真調（イラスト禁止）、日本の実景、自然光、35mm、看板文字なし、同一テンプレ内で光と色調を揃える。彩度は控えめ。
枚数の正はコード（`src/lib/templates/photos.ts` の `TEMPLATE_PHOTOS`）。デモの一覧（実績・スタッフ・品書き）は必ずこの枚数以下にしてあるので、初期状態で写真の入らない行は出ない。

| ファイル | 寸法 | 用途 |
|---|---|---|
| `hero.jpg` | 1536×1024 | 主役の1枚（外観・現場・店内の顔） |
| `scene-1.jpg` `scene-2.jpg` | 1536×1024 | 仕事の風景・店内（access 写真＋情報、booking 写真＋CTA、strengths 誌面） |
| `work-1.jpg`〜`work-4.jpg` | 1536×1024 | 実績・作品・スタイル・施設（works）。**4件まで** |
| `owner.jpg` | 1024×1536 | 代表（staff 一覧の1人目＋メッセージ、company 挨拶） |
| `staff-2.jpg` `staff-3.jpg` | 1024×1536 | 代表以外の人。**人は3人まで**（1人目は `owner.jpg`） |
| `team.jpg` | 1536×1024 | スタッフが仕事中（staff 一覧・誌面の見せ方違い、voices 主役） |
| `item-1.jpg`〜`item-4.jpg` | 1536×1024（正方形で切る） | menu を持つ業種のみ: saveur（料理）velvet（メニュー）beacon（コース）forge（プログラム）marche（商品）。credence（料金＝表だけ）は不要。**4件まで** |

- お知らせ（news）に写真は付けない。10業種とも写真の出ない見せ方（`list-rows` / `quiet`）を使う。`news-*.jpg` は作らない。
- 1テンプレあたり **11枚**（hero / scene-1 / scene-2 / work-1〜4 / owner / staff-2 / staff-3 / team）。品書きに写真を出す5業種（saveur・velvet・beacon・forge・marche）は `item-1`〜`item-4` を足して **15枚**。10業種で **合計 130枚**。
- works セクションを持たない clarity・beacon も `work-1`〜`work-4` は作る（施設の写真として持ち、お客さんが実績の部品を足したときにそのまま入る）。
- 写真を出す品書きが要る業種（saveur・marche）は「写真カード4品」と「値段の表（全品）」の2セクションに分けてある。表のほうは写真を使わない。

### 8.2 配線
- catalog / data の各セクション data に写真を割り当てる: `hero.image`、`works.items[].image`、`staff.items[].image`、`menu.items[].image`、`access` の写真、`strengths`・`booking`・`company` の写真付き変種。
- SVG 絵（art.tsx）は「写真が無いときの最後の砦」に降格。テンプレの初期状態では出さない。
- 申込で作る site.config はテンプレの写真をそのまま初期値に持つ（お客が差し替えるまで表示）→ 公開初日から完成に見える。
- `<img>` に width/height/loading を付けてレイアウトのずれを出さない。
- 旧フォルダ（luminos/nexus/prism）と 0KB ファイルは削除。

## 9. 部品を自分で組み立てる（Builder）
**目的**: お客（非エンジニア）が、14機能×5見せ方のカタログから部品を足し・外し・並べ替え・見せ方替え・中身を書き換えられる。テンプレは「最初の並び」であって固定ではない。
**現状**: エディタの「構成」で並び替え・表示/非表示・見せ方の切替はできるが、カタログから足す／外す手段が無い。

### 9.1 置き場と操作
- エディタ左パネル「構成」→「ページの部品」。一覧の各部品に [並び替え] [名前] [見せ方(5)] [表示/非表示] [複製] [削除]。削除は即時＋「元に戻す」トースト（確認モーダルは出さない）。
- 一覧の各すき間と末尾に「＋ 部品を追加」。押すと右側にカタログのドロワー（モーダルでなく、プレビューは見えたまま）。
- カタログ: 14機能を「興味 / 信頼 / 行動」の3群で並べ、機能を選ぶと5つの見せ方が **お客の色×その業種の手本内容で実際に描いた縮小プレビュー**（実コンポーネントを scale 表示、iframe 不使用）で並ぶ。押すとその位置に挿入→プレビューがそこへスクロールして一瞬ハイライト。
- 手本内容: 挿入直後に空にならない。業種ごとの手本（data.ts の既定＋8.1 の写真）を入れ、あとはクリックして書き換える。
- 同じ機能を2つ置いてよい（実績を2つ等）。アンカー id は自動で重複回避。
- プラン: planAllows を尊重。上位プラン限定の部品は薄く表示＋「おまかせプロで使えます」の一言（押すと料金へ）。

### 9.2 保存と申込
- 保存は既存 saveSiteConfig。sections[] への挿入/削除/複製、中身は field-target の規則で top-level 配列へ。
- `/start` の見せ方ステップには「部品はあとからいつでも足せます」を一言添える。組み立ては編集画面で行う。

### 9.3 合格条件
1. 部品の追加→内容変更→保存→公開サイトに反映まで通る。
2. 追加直後の部品が空にならない（写真も文章も入っている）。
3. 縮小プレビューがお客の色で描かれる。
4. 追加・削除・並び替えは100ms以内に画面が反応する（楽観的更新）。
5. 文言は一般語（追加・削除・複製・並び替え・見せ方）。
