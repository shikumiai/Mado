## 0. 一行で

**継ぎ接ぎのアプリを、意図から設計し直した1つの体験に作り替える。** 入口（ログイン）は1タップ。

---

## 1. 絶対に守ること（非交渉）

1. **本番を止めない。** 作り直しは `rebuild-v2` ブランチ + ワークツリー（`C:/dev/mado-rebuild`）で組む。
   出来上がって検収が通るまで、`main`（本番 `mado.shikumiai.com`）には触れない。切替は最後に一度だけ。
2. **別セッションの作業に触れない。** LP・会員設定・料金カードを別の Claude が編集中。そのファイルを奪わない。
3. **プラットフォームは残し、アプリを作り直す。** Next.js 16 / Vercel(hnd1) / Supabase(東京) / Stripe は正しい選択なので土台として使う。
   作り直すのは「その上で動くアプリの全部」＝設計言語・画面・認証・会員・エディタ・LP・データの持ち方。
   基盤配管まで作り直すと、利用者に価値ゼロでリスクだけ増える。ここは Lyo が覆せる。

## 2. も・げ・じょ

- **も（目的）**: 継ぎ接ぎ感を消し、Lyo が自信を持って顧客に見せられる1つの製品にする。とくに入口の摩擦をゼロに近づける。
- **げ（現状）**: 裏側（DB・RLS・描画・保存・申込）は本番で通った資産。摩擦の正体は表側＝
  「毎回同意画面を挟む」「/auth/login・/member・/start・モーダルの往復」「旧 next-auth と新 Supabase の二重認証」。
- **じょ（条件）**: ①入口は1タップ・サインイン≡サインアップ ②認証は1系統(Supabase) ③達成したい意図を起点に設計する
  ④100ms 以内に反応 ⑤箱=法人格=請求単位 ⑥本番を壊さず段階切替 ⑦2029 年に古びない。

## 3. 設計言語（UIUX憲章の適用）

- **Intent-first**: 固定画面の量産をしない。「サイトを持つ・直す・伸ばす」の意図に沿ってUIを畳む。
- **Calm + Neurodivergent-first（既定ターゲット）**: 低リテラシーの零細企業オーナーが迷わない。
  1画面1決定、平易な日本語（追加/保存/公開…一般語はそのまま。専門語は言い換えるか一言添える）。
  `prefers-reduced-motion` 尊重、視覚負荷は落とせる。
- **Ambient over modal**: 割り込みモーダルを廃す。結果・エラーはその場に薄く出す（理由を必ず添える）。
- **Sub-100ms**: 楽観的更新・skeleton・streaming を標準。保存はDB1行更新なので即反映（旧ビルド待ちを捨てた資産を活かす）。
- **Motion as primitive**: framer-motion。動きはレイアウトの一部として扱い、過剰演出はしない。
- **Luminance hierarchy / theme-aware**: 明度・透明度で階層。ライト/ダーク両対応（憲章はDark first、BTOB零細向けLPは光基調も可）。

### 視覚トークン（確定・実装は CSS 変数 + Tailwind theme）

- **色**: ブランド＝ネイビー(基調テキスト/信頼) × クリーム(地) × オレンジ(差し色/CTA)。
  アクセントグラデは既存資産 `#e84393 → #6c5ce7 → #f39c12` を「CTAと印だけ」に限定（面には塗らない）。
- **字**: 見出し=太めゴシック、本文=Noto Sans JP 系。数字は等幅寄りで金額を読みやすく。
- **形**: 角丸大(2xl)・余白広め・境界は淡線。ガラス/マテリアル質感は差し色カードにだけ薄く。
- **マスコット「むすび」**（チビ和装キツネ）を副操縦士の常在プレゼンスに。割り込まず、要所で寄り添う。
  画像生成は Lyo 手動（ChatGPT）。ここでは置き場と役割だけ定義し、実画像は生成後に差す。

## 4. 情報設計（意図の束として組む）

- **公開**: `/`(LP・「写真を送るだけ、あとは全部おまかせ」) / `/pricing` / `/legal` `/privacy`
- **入口**: `/start`（意図＝サイトを持つ）。業種→テンプレ→会社情報→**1タップログイン**→URL→公開。無料は即公開、有料はStripe。
- **会員**: `/app`（意図の束＝自分のサイト、直す、伸ばす、支払い）
  - サイト一覧 + 状態 / エディタ（見る・直す・AIに頼む の3モード、保存はDB即反映）/ 支払い（Stripe Customer Portal 直結）/ 支出の透明性
- **顧客サイト**: `/[slug]`（DBから描く。Renderer は warm-craft / trust-navy / clean-arch の3系統、**trust-navy を新規作成**）
- **管理(Lyo)**: `/admin`（顧客・MRR・編集依頼キュー。`platform_admins` 権限）

## 5. 認証（今回の作り直しの肝・Lyo の主訴）

- **1系統に統一**: Supabase Auth のみ。next-auth は完全撤去。
- **サインイン≡サインアップ**: Google はアカウントが無ければその場で作られる（標準挙動）。入口を1つにする。
- **摩擦を消す**: `prompt: consent` を外す（毎回の同意画面を消す）。redirect は最短で着地先まで一本化。
  Google One Tap もしくは単一ボタン。将来メールのマジックリンクを退避で用意。
- **着地ロジック**: ログイン成功 → org があれば `/app`、無ければ `/start` の続き（既にログイン済みとして）。
  失敗・中断はその場に理由を薄く出す（画面を飛ばさない）。
- **権限は DB(RLS) が保証**。画面側の判定は出し分けの便宜で、抜け道は作らない。

## 6. データ（第一原理で引き直す。結果は良い既存スキーマに近づいてよい）

- **箱 = orgs = 請求単位 = 適格請求書発行単位**（SaaS決済憲章11）。一度作った箱は分割・統合しない（UIと規約に明記）。
- 核: `orgs` / `org_members` / `sites` / `site_configs`(jsonb・即反映) / `site_config_versions`(履歴) /
  `assets`(Storage) / `edit_requests` / `ai_edit_usage`(メーター) / `stripe_events`(冪等) / `platform_admins` / `reserved_slugs`。
- config は jsonb 継続（Renderer/型をそのまま活かす）。検索したい項目が出たら列へ切り出す。
- 新規作成・プラン変更・Stripe 連携は service_role 経由（顧客が自分で書き換えられない）。

## 7. 課金（SaaS決済憲章の適用）

- 基本は base サブスク（おためし¥0 / おまかせ¥1,480 / おまかせプロ¥4,980）。数値は Lyo の事業判断＝据え置き。
- **base + variable の余白**を最初に置く: AI編集や機能追加は将来 outcome/credit の add-on にできる形（`ai_edit_usage` を土台に）。
  ただし **AI 税（サイレント値上げ）は取らない**。
- **セルフサービスを対等に**: アップグレードも解約も同じ手軽さ。Stripe Customer Portal を会員に直結。
- **透明性を第1級**: 今のプラン・次回請求・使用状況をその場で見せ、使う人が自分で管理できる状態にする。
- Price ID は固定せず lookup_key で引く（既存 `resolvePriceId`）。webhook は冪等（`stripe_events`）。

## 8. 実装フェーズ（Fable 設計 → Opus 5 量産 → Fable 検収）

1. **基盤**: 設計トークン(CSS変数)/Tailwind theme/ルートレイアウト/テーマ切替/共通UIプリミティブ（Button/Field/Card/Toast/Sheet）。
2. **認証**: Supabase 1タップ、着地ロジック、ambient エラー。next-auth 撤去。
3. **入口 `/start`**: 意図フロー。Phase 4 のDB申込（`signup_free_site`/`signup_pending_site`）をそのまま裏に、UXを新設計で。
4. **会員 `/app`**: ダッシュボード / エディタ（DB即反映・3モード）/ 支払い(Portal) / 透明性。
5. **顧客サイト描画**: Renderer 3系統に集約、**trust-navy Renderer 新規**。デモもエディタも本番も同じ Renderer。
6. **LP `/` と `/pricing`**: 「写真を送るだけ」。憲章準拠の1本。
7. **管理 `/admin`**: 顧客・MRR・依頼キュー。
8. **切替**: preview で検証 → `main` へ統合 → ドメイン切替。旧コード掃除。

- 実装前に `node_modules/next/dist/docs/` を確認（AGENTS.md: この Next.js は破壊的変更あり）。
- ローカル常駐サーバーは立てない。`tsc` + `build` + Vercel preview で確認（メモリ準拠）。

## 9. 切替（本番を止めない）

- `rebuild-v2` を Vercel の preview に出して実機確認 → 通ったら `main` に統合 → `mado.shikumiai.com` が新アプリに。
- Supabase は同じプロジェクトを使う（スキーマ差分があれば migration で前進）。データは0件なので作り直し自由。
- 旧 `main` はタグで退避してから掃除。
