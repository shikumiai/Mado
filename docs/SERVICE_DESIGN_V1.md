## 0. 一行で

**写真を送るだけで会社のサイトができ、X・LINE・Discord からそのサイトまでの道が、どこで切れて何人通ったかまで見える。** 月額 0円／1,480円／4,980円。運営の手は使わない。

## 1. 何の商売か（も・げ・じょ）

**も（目的）**: 小さな商売のオーナーが、自分の手でサイトを持ち、お客さんが来る道を自分で確かめられる状態を、月額で売る。Lyo の時間を1顧客あたり0分に近づける。

**げ（現状・2026-09-18 に確かめた事実）**

- 本番 `mado.shikumiai.com` は作り直し版（rebuild-v2）で稼働。実客は0。
- 申込→公開→編集は本番で通る。導線チェックは PR #6 に入っていて未 merge。
- 客を受けるための土台に穴が4つある: 問い合わせが誰にも届かない／確認メールの送信元が仮／Stripe がサンドボックス／AI編集の鍵が本番に無い（§9）。
- Codex が 9/16 に出した手動運用の導線チェック（`/pilot`）は入口から外して残置。

**じょ（条件・これを満たす設計だけ採る）**

1. 本人が自分で終えられる。運営が手を入れる工程を商品に含めない
2. 公開した初日から、人に見せられる見た目になっている
3. 月額を払い続ける理由が、画面の中に見える（数字・切れた段・仕上がり）
4. 「サイトを作る」と「道が見える」が1つの約束として読める
5. 権限は DB が守る。画面の判定は出し分けの便宜

## 2. 誰に売るか

| | 主な相手 | 二番手 |
|---|---|---|
| 誰 | SNS（X・Instagram・LINE）で集客している個人事業主・小さな店。美容・教室・ジム・飲食・士業・写真/デザイン | 工務店・建設・設計事務所（テンプレの原点） |
| 導線の形 | X → LINE → サイト → 予約／問い合わせ → Discord など | 検索 → サイト → 電話 |
| 刺さるもの | サイト作成＋導線チェックの両方 | サイト作成。導線チェックの価値は薄い |
| 届け方 | Lyo 自身の発信（X・note・LINE）で直接届く | 紹介・検索 |

**決めたこと**: テンプレは10業種のまま残す。**LP の顔は主な相手に向ける**（§11 の判断①）。理由は、導線チェックの価値が立つ層であり、Lyo の発信でそのまま届く層だから。

## 3. 約束と、約束しないこと

**約束する**

- 写真を送るだけでサイトができる。並び・配色・文章の型は本人に決めさせない
- 公開した初日から完成して見える（業種見本が入った状態で公開）
- 道がどこで切れているか、段ごとに何人通ったかが分かる
- いつでも解約できる。違約金はない。解約後もサイトは残る

**約束しない**（LP と規約の両方に書く）

- 売上や問い合わせが増えること
- 人がなぜ離脱したかの断定。出すのは段ごとの状態と人数、それに「仮説」と明示した一言まで
- X の投稿の監視、LINE や Discord の中の確認（権限を預からない限り）
- 人のテスターによる確認（Codex 版の手動運用は商品に含めない）

## 4. お客さんの流れと、段ごとに見る数字

| 段 | 何が起きるか | 画面 | 見る数字 |
|---|---|---|---|
| 1 知る | Lyo の発信・紹介・検索で LP に来る | `/` `/pricing` `/portfolio-templates` | LP 訪問数 |
| 2 名前を取る | サイトの名前を入れて空きを確かめ、1タップでログイン。その場で名前を押さえる | LP の名前入力 → `/start` 1〜2 | 名前入力数、ログイン完了数 |
| 3 公開する | 色 → 業種 → 見せ方 → プラン → 会社情報 → 確認 → 公開。無料は即公開、有料は Stripe | `/start` 3〜8 | 公開数（無料／有料）、離脱した段 |
| 4 自分のものにする | 「次にやること」を1つずつ。写真・キャッチコピー・実績・連絡先 | `/app` → 編集画面 | 仕上がり 5/5 の到達率 |
| 5 道を見る | 導線を登録 → 追跡リンクを X や LINE に貼る → 「いま確かめる」 | `/app/funnels` | 導線登録数、段ごとの通過数、切れた段の修正率 |
| 6 続ける | 問い合わせが届く、AI編集、部品を足す、数字を見る | `/app` `/app/billing` | 継続率、解約理由、プラン変更 |

段ごとの数は、いまは DB の行数でしか追えない。**§8 の管理画面に「段ごとの数」を1画面で出す**。LP 訪問数は Vercel の解析を入れてから。

## 5. 商品の構成（機能 × プラン）

価格は変えない。差は「回数」「本数」「自動」で表す。

| 予約・採用の部品 | — | — | ○ |
| 独自ドメイン | 手動対応 | 手動対応 | 手動対応 |

**決済の考え方（SaaS決済憲章の適用）**

- 土台は月額（base）。AI編集の回数は `ai_edit_usage` で数えていて、将来の追加購入（variable）の余地になる。AI を黙って値上げに混ぜない
- 箱 = `orgs` = 請求単位 = 適格請求書の単位。1つ作った箱は分割も統合もしない
- 今のプラン・次の請求・使用状況を `/app/billing` でその場で見せる。解約もプラン変更も同じ手軽さ（Stripe の顧客ポータル）

## 7. データと権限

| 表 | 何を持つか | 読める | 書ける |
|---|---|---|---|
| `orgs` | 会社＝請求単位。プラン・状態・Stripe の紐付け | 自分の会社／Lyo | service_role のみ（プラン・Stripe） |
| `org_members` | 会社とログイン利用者 | 自分 | service_role |
| `sites` `site_configs` `site_config_versions` | サイト・中身（jsonb）・履歴 | 公開中は誰でも／自分の会社 | 自分の会社（版を照合して保存） |
| `assets` + Storage `site-assets` | 写真 | 公開 | サーバー経由（縮小してから置く） |
| `inquiries` | 問い合わせ | 自分の会社 | 公開サイトから（回数制限つき） |
| `ai_edit_usage` `edit_requests` | AI編集の回数・依頼 | 自分の会社／Lyo | サーバー |
| `stripe_events` `reserved_slugs` `platform_admins` | 冪等・予約語・管理者 | — | service_role |
| `funnels` | 導線（段の並び） | 自分の会社 | 自分の会社 |
| `tracked_links` `tracked_clicks` `funnel_runs` | 追跡リンク・通過記録・チェック結果 | 自分の会社 | service_role のみ（飛び先を書き換えられない） |
| `mado_pilot_orders` `mado_pilot_applications` `mado_funnel_orders` | Codex 版の残置 | — | — |

原則: 権限は RLS が守る。他人のサイトが編集される事故を、アプリ側の書き漏らしで起こさせない。IP は保存しない。写真は Git に入れない。

## 9. いまの実装状況と、客を受ける前に塞ぐ穴

**できている（本番）**: 申込〜公開〜編集、10業種と写真130枚、部品ビルダー、認証3系統、Stripe（サンドボックス）、次にやること、管理画面の骨。

**PR #6 で待機**: 導線チェック一式、公開前チェック、LP・料金表・OG の新しい売り文句。通し確認済み。

**未着手**: 写真をまとめて入れる画面（`ONBOARDING_V1.md` §3-4）、毎日の自動チェックと通知、会員ページの段（テスト用アカウント運用）、独自ドメインの自動化、管理画面の段ごとの数。

**穴（客を受ける前に塞ぐ。順番はこの通り）**

1. **問い合わせが誰にも届かない。** `inquiries` に入るだけで、`notify()` は空。マイページにも一覧が無い。→ 送信元メールを決めて、本人に通知＋マイページに一覧
2. **確認メールの送信元が仮。** Supabase 既定の送信元で、送信数に上限がある。→ 1 と同じ送信元で SMTP を設定
3. **Stripe がサンドボックス。** 実客は払えない。→ 本番鍵・Webhook・価格の再作成（`stripe-setup.mjs` は冪等）
4. **AI編集の鍵が本番に無い。** `ANTHROPIC_API_KEY` が Vercel に無く、OpenAI かデモに落ちる。モデル名も古い。→ 鍵を入れ、モデルを今のものに
5. Vercel が Hobby。商用利用は Pro が規約上の前提。→ Lyo の判断（§11 ④）
6. 残骸: `/pilot`（Codex 版）、`/member/site`、`layout.tsx` の古い JSON-LD、`/lp/*`。→ 掃除か判断
